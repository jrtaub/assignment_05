One of the biggest things I learned was the importance of understanding the grain of the data, since each row represented one employee being paid for one week. I used concat with ignore_index=True to combine the weekly files while keeping track of their lineage through the source file column. I also learned how to clean inconsistent data using vectorized .str methods and convert dates using pd.to_datetime with a specific format. Using errors="coerce" helped handle invalid dates by turning them into NaT, and .dt allowed me to extract information from the dates.

Another important part of this assignment was understanding the difference between long and wide data. I used groupby with named aggregation and reset_index to summarize payroll information, while pivot_table with fill_value=0 helped organize hours by employee and week. I also learned how melt can turn wide data back into long data. One specific challenge I faced was when my Streamlit app failed the test that checked for employees who were not on the roster. For example, the test uploaded a file containing employee E77, but my data-cleaning function changed the ID to E077. Even though my app was correctly identifying the employee as unmatched, the test still failed because my warning displayed E077 instead of the original E77. I fixed this by using the original employeeid column when displaying the warning while keeping the cleaned employee_id column for matching. This helped me understand why preserving the original data is important, especially when troubleshooting errors. In the future, I want to test each step of my pipeline separately and compare the original and cleaned data before making changes, rather than repeatedly changing my code without fully understanding what was causing the error.
